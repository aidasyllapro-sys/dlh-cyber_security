## Priority summary

- **GAP-002** (P1): The single Conditional Access exception (`compliant_device` overriding a medium Identity Protection risk score) is the point that let the stolen credentials be used at all — fixing it would have stopped the entire intrusion chain before it started.
- **GAP-004** (P1): Detection already worked here (alert fired in 13 seconds) but produced no containment action, so the highest-leverage fix in this incident is turning an existing high-fidelity alert into an automatic host isolation.
- **GAP-008** (P1): The LSASS credential-theft step had zero detection of any kind and is the pivot that made every subsequent lateral-movement step possible — closing it removes the mechanism the attacker used to move past the first compromised host.
- **GAP-009** (P1): Ticket reuse was already captured in the logs but never escalated; turning that existing signal into a routed SOC alert is a detection gap, not a new-control gap, making it fast to close.
- **GAP-011** (P1): This is the last point before confirmed PHI exposure (14 patients, HIPAA breach presumption under 45 CFR 164.402) and currently has no control of any kind watching bulk file access on the LIS share.
